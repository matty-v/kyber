# Kyber v1.8.0

Changes since v1.7.0. Prepared for publication on 2026-09-27.

## New features

- **Move an agent between machines and installations (disk export and
  import).**
  - **Export:** from Agent Detail, export an agent's persistent disk as a
    verified ZIP with a versioned manifest.
  - **Import:** the Create Agent wizard, or `POST /api/v1/agent-imports`,
    creates a new agent from an export or from an uploaded archive. The new
    agent boots only after its restored volume is checked against the archive.
  - **What moves with it:** the whole agent, not just its disk:
    - model, prompt and flags, resources, soul, profile and avatar, public
      capabilities, A2A peers, and the identity repo;
    - scheduled jobs, which arrive **paused**;
    - webhook bindings, which arrive **disabled** with new signing secrets, so
      nothing fires twice before cutover.
  - **User secrets:** the values are copied inside the cluster when the source
    is an export on the same installation. From an upload, their keys are
    listed for you to re-enter.
  - **Cutover checklist:** lists everything left to do.
  - **Credentials:** harness login files are never restored, so the new agent
    signs in with its own credential. Files shipped by the base image are no
    longer flagged as credentials or crontabs.
  - **Uploads:** they go in 32 MiB parts, so multi-gigabyte archives pass
    proxies such as Cloudflare. Exports and uploads can be deleted before
    retention ends.
- **Switch an agent's harness in place.** Move an existing agent between Claude
  Code, Codex and Hermes on the same volume, including across auth modes. It
  keeps its disk and transcripts, then asks the target harness to authorize.
- **Custom inference endpoints.**
  - Point a Hermes or Codex agent at an OpenAI-protocol endpoint that Kyber
    does not host (`spec.inference`).
  - Set its API key from the console, with no manual Secret needed.
  - Self-hosted endpoints report their served context window.
- **Agent avatars in the console.**
  - Upload, replace or remove an avatar from General settings. It shows in the
    agent list and the agent header.
  - Images are cropped square, scaled to 256 px and stripped of metadata such
    as EXIF and GPS.
  - Avatars now work on every installation, with no object store required.
- **Pause jobs and disable webhooks.**
  - Scheduled jobs can be paused and resumed. A paused job never fires, and
    *Run now* refuses it.
  - Webhook bindings can be disabled. A disabled binding answers `409` after
    verifying the signature.
- **Hermes reports its goal**, like the other harnesses.
- **Identity-repo capability reporting.** `GET /config` says which identity-repo
  modes the installation supports. Create requests it can't serve are rejected
  up front, and the wizard offers only the modes that work.

## Fixes

- **Run now:**
  - It uses the job's saved prompt and its `exclusive` and `clearContextAfter`
    flags, so it works immediately after a job is saved.
  - It reports a failed or skipped dispatch instead of always answering `202`.
  - It still works against agent images from before this release.
- **Credential saving:** saving an OAuth or API-key credential never answers
  `500` once the credential is stored, even when the agent is changing state.
- **API-key agents:**
  - Creating one without a key is rejected with `400` naming the field.
  - A pod missing its Secret shows the kubelet's reason right away.
- **Identity repos:**
  - A stale `index.lock` no longer blocks identity sync, and `kyber-skills`
    never takes the index lock.
  - New identity repos get a single scaffold commit. Scaffolding tolerates
    GitHub's brief replication lag on a newly generated repo.
  - Agents waiting on an identity repo show as `Creating` and recover on their
    own.
- **File secrets:** these can keep file names such as `vault-cert.pem`.
  Key-value secrets keep the environment-variable naming rule.
- **Skills:**
  - `kyber-skills install PATH` installs from the given path.
  - Skills that exist only on disk are reported as `local`.
  - Folders without a `SKILL.md` are no longer flagged.
- **Hermes:** agents on slow custom endpoints get a 900 s stream timeout
  instead of 180 s.
- **Tables:** tables sort numeric suffixes naturally (`agent-2` before
  `agent-10`).

## Security

- Responses whose content type is sniffed never resolve to HTML or XML, which
  closes a reflected-XSS path.
- Dependency updates address `fast-uri` (GHSA host-confusion and SSRF
  advisories) and `uv` in the Hermes image (GHSA-2cv4-cqwr-gwf7). The dev-only
  `esbuild` advisory (GHSA-g7r4-m6w7-qqqr) is pinned out of the build.

## Upgrade notes

**New archive store:** disk archives are **enabled by default**
(`agentArchives.enabled: true`, `storage.backend: builtin`). The first upgrade
creates an `archive-store` Deployment and Service, a token Secret, and a 100Gi
`ReadWriteOnce` PersistentVolumeClaim on the default StorageClass (or
`agentArchives.storage.builtin.storageClassName`). The store follows the
control plane's node placement.

- **macOS, WSL2 and k3s:** nothing to do. The volume is a `local-path`
  directory, and its size is a request, not an allocation.
- **GKE:** the default `standard-rwo` class provisions a **billed** 100Gi zonal
  disk. Set a smaller `agentArchives.storage.builtin.size` before upgrading if
  you don't want that (a volume can grow later but never shrink), or use
  `backend: gcs`.
- **EKS:** clusters on 1.30 and later have **no default StorageClass**. Use the
  updated EKS preset (`storageClassName: kyber-ebs`), set the class yourself,
  or use `backend: s3`. Without one, the chart refuses to render, so the
  upgrade stops before it changes anything instead of leaving the volume
  Pending.
- **Anywhere:** `agentArchives.enabled: false` turns the feature off.
- **PostgreSQL:** disk archives need it (`KYBER_POSTGRES_URL`). Without it,
  the feature reports itself unavailable.

See [upgrading: disk archives](../upgrading.md#disk-archives-the-built-in-archive-store-v180)
for the self-upgrade path.

**CRDs:** apply them before upgrading; the self-upgrade Job does this for you.
All CRD changes are additive:
- `spec.inference`
- `spec.jobs[].paused`
- `spec.inboundBindings[].disabled`

Existing agents keep their jobs active and their bindings enabled.

**RBAC:** the control-plane ClusterRole adds `delete` on `configmaps`.
Avatars are stored in ConfigMaps owned by each agent.

**Avatars stored before this release:** avatars in the durable-tasks object
store still display. They move to a ConfigMap on the next upload, and are
removed when their agent is deleted.

**pwa-views:** now at 0.62.0 and versioned independently.
- Its React peer range widened to `^18.3.0 || ^19.0.0`, so existing hosts keep
  working.
- `@tanstack/react-table` v9 is bundled and is not a peer dependency.

No incompatible API changes are known. New endpoints:
- `switch-runtime`
- agent exports, archive uploads and agent imports
- archive `DELETE`
- `profile/avatar`, now documented

Publishing this release does not install it on any cluster. Apply it through
the installation's update mechanism, then verify the reported version and the
agent rollouts.

## Validation

- Required main CI passed at the release candidate, including integration,
  CodeQL, the pinned A2A contract, and the official HTTP+JSON TCK.
- Live testing on the GCP development install (`kyber-dev`):
  - **Disk export and import:** exported a 1.49 GB agent, uploaded the archive
    through the public Cloudflare URL, and restored it on a second machine with
    its configuration, paused jobs, disabled bindings, copied secrets and
    resumed conversation. The harness login stayed behind.
  - **Harness switch:** Claude Code → Codex in place.
  - **Avatars:** upload, replace and removal in the console, on an install
    with no object store.
