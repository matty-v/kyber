# MAT-106: Ori Harness compatibility with Kyber

Status: limited live Codex endpoint and pod-replacement canaries complete; **no production routing decision**. Date: 2026-10-09.

## Evidence and versions

- Inspected Kyber `main` at `eb6e3c4` and the [v1 harness contract](../architecture/agent-harness-contract.md). Repository defaults are Claude Code `2.1.119` and Codex `0.146.0` in Helm values. The datawire cluster canary later used control-plane/Codex image tag `1.8.0-3-geb6e3c4` and resolved Codex CLI `0.162.0` at boot; the exact image digest was not captured.
- Inspected the Linux Ori CLI `0.15.6+4855f79`, SHA-256 `d3525283d0431197943445c499edf8d790d13816752efd0e373afe2da75e035c`, using `ori --version`, `ori help claude`, and `ori help codex`. This confirms command descriptions, not a successful authenticated turn. Its downloaded binary remains outside this repository.
- Read the current [Ori Harness](https://openrouter.ai/docs/guides/ori/harness), [Ori Configuration](https://openrouter.ai/docs/guides/ori/configuration), [Ori file-writing](https://openrouter.ai/docs/guides/ori/files), and [Ori Codex](https://openrouter.ai/docs/guides/ori/codex) documentation. Upstream behavior can change; pin and retest exact images before enabling a route.
- An operator-injected OpenRouter key became available during this spike. `GET /api/v1/key` reports no per-key spending limit; Matt waived a cap for the bounded investigation. A direct `POST /api/v1/responses` smoke test with `cohere/north-mini-code:free`, `reasoning.effort=none`, and a 32-token cap returned a completed `OK` message with reported cost `$0`. Other free-model probes returned incomplete reasoning-only responses or upstream 429, so model-specific qualification is necessary.
- The GKE auth plugin was installed outside this pod's `PATH`; after gcloud reauthentication, a fresh, channel-free `ori-canary-20261009` Agent ran in `kyber-system` with Codex `0.162.0` and `spec.inference` aimed at OpenRouter `/api/v1`. Its per-agent Secret was referenced as `OPENAI_API_KEY` in the pod spec; the Secret value was not printed. `/etc/codex/managed_config.toml` inside the durable root selected `kyber-endpoint`, the expected model, the Responses wire API, and the OpenRouter base URL. Kyber reported `Running`, `currentModel=cohere/north-mini-code:free`, and fresh runtime capability evidence. A tmux-delivered prompt returned `OK` after 28 seconds. The candidate's free-model generation did not add an observed charge; OpenRouter usage from the separate Eval experiments reconciled later. This is one interactive turn, not channel/restart/auth/task conformance.
- The turn also invoked Kyber's `kyber_request_reply.set_goal` tool before replying, despite the prompt requesting no tools. This may reflect Kyber's own goal workflow, but it means the canary was not tool-free; do not treat its prompt as an isolation check. A local `ori codex` launch against the same free model returned `OK` with `--reasoning-effort minimal`; `none` is rejected by Ori's Codex adapter. That local launch inherited this agent's existing hooks and is **not** a clean managed-pod comparison. No `ori claude` turn or Kyber-managed Ori launch path has run. The disposable Agent, its managed resources, and its inference Secret were deleted after the result.
- A second channel-free Agent, `ori-restart-20261009`, repeated the direct Codex `spec.inference` route with `requestReplyEnabled=false`. Its initial turn returned exact `CANARY-ONE` with no visible tool call. We deleted only its pod (UID `a913f02b-18e8-498c-9f98-f2c647d151cd`) to exercise recovery. The Agent briefly entered `Failed` at `05:09:37Z`; controller events recorded two `PodDied`/`AgentCrashed` transitions and `restartCount=2`, then `Failed → Creating` after the crash backoff. The replacement pod (UID `cc1b7540-42f4-45d9-b73c-f6e227e24d15`) reached `Running` at `05:11:34Z`, and its first turn returned exact `CANARY-TWO` in 35 seconds. The Codex image digest was `sha256:78aaa54430a04e6bc60f54db710d94734d3b7bf1cb267edf9208e4d83da8f4d1`. The double restart count is tracked in MAT-112; this one recovery does not prove native transcript resume, auth recovery, channel delivery, or Ori wrapper behavior. We deleted this Agent, pod, PVCs/PVs, managed resources, and inference Secret after the test.
- A third channel-free Agent, `ori-wrapper-20261009`, tested the pinned Ori CLI *inside* a managed Codex pod. We copied the hash-verified Ori binary into this disposable pod and launched `ori codex --model cohere/north-mini-code:free --reasoning-effort minimal exec --skip-git-repo-check` in a separate tmux window with the agent-scoped OpenRouter credential and update/telemetry policy variables. It returned exact `WRAPPED-ONE` with exit code 0, but Codex reported `provider: kyber-endpoint`: Kyber's existing managed config still selected the direct provider, so this is **not** evidence that Ori's provider injection works under Kyber policy. Ori warned that the model was absent from its catalog and passed it through. The Codex goal hook ran despite the no-tools prompt. A preliminary `ori --version` probe without policy variables wrote update/telemetry files under `.ori`; policy must be present even for probes. An ad hoc `kubectl exec chroot` attempt crashed Bun because that shell lacked the normal `/dev` mounts; the tmux run used the actual managed runtime mount context and succeeded. The pod image digest matched the second canary. We deleted the entire disposable Agent, pod, managed resources/storage, and inference Secret afterward.
- A fourth channel-free direct endpoint Agent, `ori-auth-20261009`, started with an invalid credential Secret. A tmux turn returned `401 Unauthorized: Missing Authentication header` from OpenRouter, while Kyber continued to report `Running` and idle. Rotating the Secret to the valid operator key did not replace the pod or change the phase during the observed 20-second window. After an explicit `desiredPhase=Restarting` request, a new pod (old UID `8eead0fa-1683-4c73-90f9-51310c32beb8`, new UID `c7ae435d-2b8f-496f-925e-fccf793c5c6d`) started and returned exact `AUTH-RECOVERED`; Kyber again reported `Running`. This establishes a recoverable credential path but exposes missing automatic auth-state reporting and Secret-rotation rollout for endpoint agents. The canary, its storage, managed resources, and Secret were removed. The auth-state and rotation gap is tracked in MAT-113.

Ori documentation says Claude Code and Codex use launch-time catalog checks, not in-session catalog/routing toggles. An unknown model ID may pass through unchanged. Kyber must validate the selected OpenRouter model and supported harness combination itself; it cannot treat Ori's launch check as a safety gate. OpenRouter's catalog includes models that may fail a given harness's tool or wire requirements.

Two current Kyber paths need special review even for direct Codex routing. `pkg/api/model_validation.go` only checks IDs with the native `gpt-` prefix, so an `author/model` OpenRouter ID bypasses the current write-time catalog check. `docs/runtimes.md` records that an endpoint agent in `NeedsAuth` is still offered the native Codex login control, although rotating its endpoint Secret is the relevant recovery action. Neither should be presented as finished UX.

## Security and launch constraints to verify

1. Use one OpenRouter credential Secret per agent, injected as `OPENROUTER_API_KEY` only for the selected route. Set `ORI_FORCE_OPENROUTER_API_KEY=1`; avoid `ori login` and its file-backed saved key. Confirm the CLI does not copy the key into workspace logs or upstream config. Review Ori's `.ori/logs` (which can contain prompts/repo content), keep them out of git, and account for them in disk export and retention policy.
2. Pin Ori's binary and upstream CLI/image. Set `ORI_DISABLE_UPDATES=1` and `ORI_TELEMETRY=0` before **any** Ori invocation, including version probes; keep installation and background updates out of the agent's runtime. Test actual policy precedence in the pinned version.
3. Set `ORI_FALLBACK_MODELS` to an empty value and test that no implicit model fallback occurs. Ori's documented default contains two alternate model slugs. Neither a model failure nor a missing OpenRouter credential may silently use an existing subscription or another paid model.
4. Do not allow agent-owned `.ori/config.json`, `--settings`, `--setting-sources`, or Codex user config to redirect a managed launch or override Kyber's hook, model, endpoint, or credential policy. Identify which Ori CLI settings are injected where and verify precedence by inspecting a disposable agent's effective config.
5. Explicitly disclose that OpenRouter and the routed upstream provider can process prompts and that OpenRouter, not Kyber, enforces workspace guardrails/budgets. Provider routing may change or be unknown. Kyber token cost estimates are not OpenRouter invoices.

## Disposable canary plan

Use fresh, isolated agents with no production identity or channels initially. A provider-enforced key or workspace budget is the normal control for paid canaries; Matt waived it for this bounded free-model investigation. Never paste a key into an issue or test log. Record image digests, CLI versions, exact model ID, config hashes/paths (not contents containing secrets), and UTC times. For each candidate route:

1. Confirm boot chooses OpenRouter explicitly and rejects a missing key before the harness starts. Inspect the effective native config and process environment without printing the key.
2. Send one interactive prompt and one tool-using prompt, then a platform channel message. Confirm outbound response, transcript, token usage and model identity; compare OpenRouter activity/cost to Kyber estimates without treating equality as expected.
3. Restart session and replace the pod. Confirm persistent identity/skills/MCP, native resume, reporter recovery, no config drift, and a subsequent successful turn.
4. Revoke or rotate the key, then simulate provider/network errors. Confirm `NeedsAuth` only for confirmed auth loss, bounded recovery elsewhere, and no fallback to a subscription or second model.
5. Exercise model change and an invalid/blocked model. Verify controlled restart, honest catalog and price states, and fail-closed job/task hooks before enabling those capabilities.

The canary must be disposable and must not mutate an existing subscription agent. `MAT-108` remains gated until these results select a route and its spec is revised. A production implementation would then need reviewed changes across API/CRD mode representation, Secret handling, image/start scripts, reporters, descriptor/capability gates, PWA, conformance fixtures, and release docs. It may be smaller for Codex if direct `spec.inference` meets the contract.
