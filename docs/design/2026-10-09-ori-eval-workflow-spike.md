# MAT-109: Ori Eval workflow fit for Kyber

Status: bounded synthetic comparison complete; product decision proposed, **not a production eval integration**. Date: 2026-10-09.

## Decision

Offer Ori Eval initially as a documented, opt-in **external evaluation job** for comparing candidate OpenRouter models on sanitized Kyber-like tasks. Do not add a Kyber API, CRD, console action, or background job under MAT-110 yet. Ori Eval runs its own temporary `ori` harness; it does not exercise a persistent Kyber Claude, Codex, or Hermes agent, its channels, hooks, tools, identity, or restart path. Present its results as screening evidence only. A later Kyber integration needs a separate, consented execution and data-retention design plus a live harness conformance result from MAT-106.

The product workflow should use an isolated workspace and a dedicated OpenRouter key with a provider-enforced spend limit. Matt explicitly waived that cap for this small synthetic investigation; the existing key still reports `limit: null`. The investigation bounded models, cases, turns, tokens, and wall time. A local assertion such as `toCostAtMost` observes cost **after** a request and is not a spending control.

## Evidence

- Read the current [Ori Eval guide](https://openrouter.ai/docs/guides/ori/eval) and the bundled `ori eval docs sdk`, `running`, and `lifecycle` references in Ori CLI `0.15.6+4855f79` (same pinned binary and checksum recorded in [MAT-106 PR #311](https://github.com/matty-v/kyber/pull/311)). `ori eval --list --allow-no-key` and `--dry-run --hermetic --no-history` discovered four synthetic tests without model calls. Bun `1.4.2` was installed under `/tmp` only for this pilot; neither binary nor an API key entered the repo.
- The [opt-in fixture](../examples/ori-eval/kyber-synthetic.eval.ts) has two synthetic cases: return a `clamp` JavaScript function, and classify a fictional 30-day refund request as `APPROVE_REFUND` or `ESCALATE`. It compares `cohere/north-mini-code:free` with `nvidia/nemotron-3.5-lightning:free`, requests `reasoning.effort=none` and at most 256 output tokens, and requires completion, a deterministic phrase, elapsed time under 90 seconds, and reported cost under $0.001. `pilotCases` allowed `--pilot 1` to sample one coding case per model before the full run. No tools or Kyber channels were exercised.
- `--pilot 1 --hermetic --no-history --features <empty directory>` excluded workspace instructions and skills while retaining Ori's own skills. The pilot result identified the execution harness as `ori`, not Kyber's persistent runtime. `--no-history` suppressed the summary history, but the temporary workspace still held Ori session history; a production job must govern that data and delete it after artifact extraction.
- Each sampled case made two OpenRouter generations. The requested `:free` candidate generation had `total_cost: 0`; a separate generation with model `typesafe/jev-1.13-20260917` had `api_type: decisions` and `total_cost: 0.000061404` (1280 prompt and 58 completion tokens). The pilot included this in `costUsd`. We have **not established the purpose or configurability of that second call**. The two pilot invocations (one stopped after a zero-cost assertion failed, one completed) increased `/api/v1/key` usage from $0.344051046 to $0.344296662, exactly $0.000245616, or four such charges. Thus free candidate slugs do not imply a free Ori Eval workflow. `ORI_FALLBACK_MODELS` was explicitly empty; further investigation must distinguish Ori internal evaluation/selection from fallback before claiming either.
- A first full run used a freeform support answer and failed both support tests because `toMention("30 days")` rejected equally valid `30-day` and `30‑day` wording. One Cohere answer also escalated a 10-day request, contrary to the synthetic policy. Replacing that brittle phrase check with a plain `expect()` exposed another Ori reporting limit: its report marked model correctness as *contradicted* because plain Bun assertions are not attributed to the candidate run. The checked-in fixture instead asks for a single policy label and uses Ori's `toMention` matcher so the report can attribute failures.
- The checked-in four-case comparison passed 4/4 tests (one run per case/model), with no correctness winner. Cohere averaged 2633 ms over its two cases; NVIDIA averaged 1276 ms. Each model's two runs cost about $0.000124, entirely from separate `typesafe/jev` Decisions API calls; candidate generations cost $0. The exact four ancillary costs were $0.000061404, $0.000062622, $0.000061404, and $0.000062622, totaling $0.000248052. OpenRouter generation records matched the Ori terminal usage. The report's `Served by` field mixes candidate and ancillary providers (including TypeSafe); it must not be read as the provider that served the requested candidate alone. Two synthetic samples per model do not establish reliable quality or latency superiority. No live Kyber agent was used for this Eval run.

## Proposed opt-in job contract

1. The operator starts a manually triggered CI or local job with a dedicated, provider-capped OpenRouter Secret. Never load credentials from a cloned project's dotenv or persisted Ori login. Set `ORI_FORCE_OPENROUTER_API_KEY=1`, `ORI_DISABLE_UPDATES=1`, `ORI_TELEMETRY=0`, and `ORI_FALLBACK_MODELS=''`. Pin Ori, Bun, fixture revision, candidate model IDs, and selected providers in the run manifest.
2. Use a disposable workspace with a fixture repository containing only approved synthetic or redacted prompts. Run `ori eval --list --allow-no-key`, then a `--dry-run --hermetic --no-history` import check, then a one-case-per-model pilot. Use an explicitly empty or reviewed `--features` directory. Inspect the context inventory Ori prints before model calls. Wrap **every** case list with `pilotCases`; a helper or second unwrapped list can escape the pilot guard.
3. Before a routine full run, confirm the account's enforced key/workspace limit and pilot's actual usage through OpenRouter generation records. Bound wall time, process concurrency, cases, turns, models, and token budgets. Do not rely on Ori's pilot estimate or matchers as an authorization ceiling. Stop on unknown extra models, unexpected provider routing, failed assertions, or a cost deviation.
4. Export a small report with fixture revision, candidate IDs, Ori version, case counts, pass/fail, duration distribution, OpenRouter billed cost, and a clear distinction between candidate and ancillary generations. Do not store raw prompts, completions, secrets, or Ori history in a public PR artifact. Retain only approved aggregate results; delete the temporary workspace and logs after reporting. Explain that the result screens models and is not evidence of Kyber's agent behavior.

## MAT-110 boundary and follow-up

Revise MAT-110 to a documented opt-in job if Matt wants this screening workflow. Do not implement a console/API/CRD eval launch until there is an explicit product need, a privacy/retention design, spend controls, and a tested Kyber runtime path. Before making model recommendations, determine what triggers the ancillary `typesafe/jev` request and whether it can be pinned, disabled, or budgeted; add representative, repeated, reviewed cases and tool-use checks. A separate live Kyber canary is required to claim harness or channel compatibility.

## Review notes

The first draft risked interpreting the pilot's positive `costUsd` as a paid candidate or billing estimator. Generation records and key-usage delta show an actual ancillary paid request. Later full-run review found an overly strict wording assertion and a reporting mismatch when plain Bun `expect()` was used. The versioned fixture now uses only attributable Ori matchers. Its four passes are deliberately not reported as a model-quality winner.
