# Local usage metadata boundary (MAT-117)

**Status:** implemented in MAT-119–MAT-125 and merged on 2026-10-12. This document records the original source audit and design; references below to the "current" collector and proposed behavior describe the pre-implementation baseline. For shipped behavior, see [Metrics data flow](../architecture/metrics-data-flow.md), [the API contract](../../test/contract/openapi.yaml), and [the operator telemetry guide](../operator/telemetry.md). The old `/api/v1/metrics/tokens` route returns 404, and no LiteLLM pricing data is installed.

## Product boundary

Kyber records what a local harness actually observed about model usage and exposes it for external accounting. A configured endpoint is a route, not proof of the provider that ultimately served a request. Missing token classes and providers stay unknown. Kyber does not derive dollar costs, read invoices, fetch rate catalogs, or store prompts, responses, or credentials in usage records. Context-window budget remains a separate live-session view.

Route audit: native subscription and direct API routes can both provide the same harness source fields above; neither makes a billing provider observable by itself. For a gateway or custom endpoint, persist the configured route type and a safe endpoint identifier separately from any locally reported upstream provider. The current Claude and Codex sources do **not** establish an upstream provider. Hermes's `provider` value is a route label. A model ID or catalog provider must never fill `observedUpstreamProvider`.

The current `/internal/agents/{name}/token-usage` POST is a context snapshot, not a billable event stream. `computeTokenDelta` differences latest input/cache counts as if they were cumulative, so equal-sized successive calls can count only once. A missing five-minute snapshot, pod restart, model change, or reporter reset can re-add or lose counts. The Redis time series and Prometheus fallback group by agent and model, discard route/provider provenance, and can disagree after gaps. `GET /api/v1/agents/{name}/token-usage` may return 503 when context-window metadata is unknown even when token evidence exists. None of these legacy totals should be relabeled authoritative.

## Proposed event and collection contract

`usage.v1` is one immutable record per finalized local usage event, with a versioned source identity. Required envelope: stable `id`, `agent`, immutable `agentUID`, `observedAt`, `ingestedAt`, `runtime`, `sourceFormat`, `sourceVersion`, `sourceIdentity`, and `coverage`. The control plane resolves `agentUID` from the authenticated Agent on ingest; neither the reporter nor a caller may choose another Agent's UID. The record carries `configuredRoute` (`native`, `direct-api`, `openrouter`, or `custom`), a non-secret route identifier, `model` plus `modelEvidence` (`observed` or `configured`), and `observedUpstreamProvider` only when the local source explicitly supplies it. Keep a separate `reportedProviderLabel` for a harness label such as Hermes `openrouter`; do not promote that label to upstream attribution.

Token counts are nonnegative integer **tokens**. `inputUncached`, `output`, `cacheRead`, and `cacheWrite` are nullable individually: `null` means not reported; `0` means reported as zero. `output` includes reasoning output when the harness already includes it. Preserve only an allowlist of source-native numeric counts and token semantics in `rawUsage` alongside normalized values. Never copy a raw transcript/log line, file path, prompt, response, or credential into this field. A correction is a new event referencing the superseded event, not an in-place rewrite of the original evidence. The accepted aggregate excludes the superseded event and includes its replacement exactly once; both remain visible in detailed evidence with their correction relationship.

Reporters scan every new finalized event, not merely the latest snapshot. Each source cursor is durable on the agent PVC and advances only after the control plane acknowledges a durable insert. The control plane enforces a unique `(agentUID, runtime, sourceIdentity)` key and returns the same acknowledgment for a retry. This prevents a deleted Agent's name being reused from colliding with another Agent lifetime. A transaction inserts the event and updates derived aggregates together. Session/rollout rotation begins a new cursor namespace; repeated lines, process restarts, and transport retries are deduplicated by source identity. For Codex, qualification must establish a call-level key or derive an accepted delta from monotonic totals; repeated `last_token_usage` observations must not be counted twice. A truncated file, missing identity, unsupported source shape, or unparseable timestamp records a coverage gap rather than silently fabricating zero usage. Events without safe identity can be surfaced as incomplete observations but cannot enter authoritative sums.

For each time window, coverage reports first/last observed event, known gaps, source versions, and which token classes are complete. A missing source interval is `unknown` coverage even when no reporter can measure the number of lost calls; `gapCount` counts detected gaps only and is never interpreted as a complete lost-call count. Aggregation is exact integer addition of accepted events, never `safeDelta` on snapshots. Group by runtime, model, configured route, upstream provider status/value, and token class. For each class, expose the sum of reported values and counts of events with reported versus unknown values; a partial sum is explicitly marked incomplete and cannot be presented as a total. Unknown upstream is its own group; it cannot be silently merged into a known provider group. Keep context snapshots for the live token-budget UI under their existing meaning.

## Proposed external API

- `GET /api/v1/usage/events?agent=&start=&end=&runtime=&model=&route=&upstreamProvider=&limit=&cursor=` filters by `observedAt` and returns events in `(ingestedAt,id)` order, a stable opaque next cursor, and coverage metadata. The first page pins an immutable ingestion snapshot in the cursor so late-arriving events cannot move between pages; events committed after that snapshot appear in a fresh query. The implementation must preserve that bound across transactions, including a late commit whose timestamp sorts earlier than a previously returned row. `limit` defaults to 100 and caps at 500. A provider filter can explicitly request `unknown`; omission includes both known and unknown without merging them. Names and time ranges use existing auth and validation rules.
- `GET /api/v1/usage/aggregates?start=&end=&agent=&runtime=&model=&route=&upstreamProvider=&bucket=day&limit=&cursor=` returns integer token sums partitioned by those dimensions, reported/unknown event counts per token class, event count, detected gap count, and completeness. A class with no reported values has a `null` sum; a class with mixed reported and unknown values has a partial sum plus an incomplete flag. Daily buckets are proposed for longer retention; unbucketed bounded windows can support external cost calculations. The endpoint never emits a dollar amount. Its cursor pins an immutable ingestion snapshot as the events API does; implementations must compute from events in that snapshot or retain versioned aggregate buckets, rather than paginate mutable current buckets. Corrections committed later appear in a fresh query.
- Both endpoints document UTC timestamps, inclusive start/exclusive end, token units, null-versus-zero, deduplication, source/version, coverage, pagination, retention, and 400/503 behavior. An `agent` name filter resolves to the currently authorized `agentUID`; name reuse must not expose a prior Agent's records. Authorization scopes must not expose another tenant's agent or private endpoint URL. A custom route identifier is an opaque random ID persisted with one Agent route configuration revision, not a hash of a guessable hostname; changing the route creates a new ID.

**Retention proposal for review:** 90 days of detailed events and 13 months of daily aggregates, configurable per installation. This is a product/storage choice, not a measured requirement. A deletion must erase records for the exact `agentUID` under the same ownership policy as other agent data, even when a new Agent later receives the same name.

## Component change and cutover

| Current component | After MAT-117 |
| --- | --- |

| LiteLLM rate projection/loader (`pkg/metrics/litellm.go`, `rates.go`, `cmd/fetch-provider-rates`), generated rates and Helm ConfigMap/mount/env/value, weekly refresh workflow, pricing preflight and tests | **Delete.** No runtime or CI price feed remains. Retain `pkg/metrics` summary and Prometheus query code used by other panels. |

## Implementation sequence

1. Capture source events and coverage alongside existing context snapshots. Validate golden multi-call fixtures for Claude, Codex, and Hermes, including equal input counts, cache classes, replay, restart, model/route switch, truncation, missing provider, correction/supersession, and mixed known/unknown token classes. Test late ingestion during paginated reads so a caller can complete one snapshot and then see the late event in a fresh query. Compare the event sums to representative local source traces before claiming accuracy.
2. Expose the new endpoints and document their semantics. Backfill **no** legacy snapshot-derived totals into the authoritative event store; mark the pre-cutover interval unavailable.
3. Move the PWA Token Usage panel to new token/model/route/provider aggregates and coverage indicators; remove “Est. cost (USD)” and `priced`/`unpriced`. Keep context-window budget separate. Stop presenting dollars in agent and fleet views.
4. In the same release that switches the PWA to the new usage API, remove `/api/v1/metrics/tokens`, `costUsd`/`priced`, the LiteLLM rate refresh workflow, vendored rates and ConfigMap, pricing code/tests, and pricing claims in docs. The old route returns 404. Keep `/api/v1/agents/{name}/token-usage` as a **context snapshot** under its documented name. No old estimate is carried into the new records. Matt explicitly chose no migration grace period on 2026-10-11.

## Decisions and implementation slices

The shipped defaults are 90 days of detailed events and 13 months of daily aggregates. Custom endpoint route IDs are opaque; the usage API does not expose the hostname. The legacy cost API and price feed were removed at cutover, with no compatibility window, per Matt's 2026-10-11 direction.

Implementation was split into: (1) source fixtures and safe per-call capture (MAT-119); (2) durable idempotent ingest with gap tracking (MAT-120); (3) Claude, Codex, and Hermes reporting and route provenance (MAT-121–MAT-123); (4) detailed/aggregate API contract tests (MAT-124); (5) PWA transition and removal of Kyber pricing dependencies (MAT-125).
