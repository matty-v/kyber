# Changelog

> Kyber's public versioning starts at **v1.0.0**. The project was developed
> privately through an internal release line (v1.3.6–v2.7.1) whose history,
> tags, and changelog live in a private archive repository. This changelog
> covers the open-source line only.

## Unreleased

Initial public release (targeting **v1.0.0**): the full Kyber platform —
control plane, node agent, Agent/Machine CRDs, Claude Code and Codex runtimes,
Telegram/Discord channel sidecars, the PWA, Helm chart, and Terraform
profiles — licensed under Apache 2.0.

Notable changes made on top of the final internal release (v2.7.1) while
preparing the code for open source:

- Feature (agents, api, pwa): **an agent's skills are now visible, and provably real.** Every Kyber agent already kept skills at `skills/<name>/SKILL.md` in its identity repo, linked into both runtime homes at boot; that contract is now enforced and surfaced. A new `kyber-skills` tool in both runtime images gives agents one idempotent command (`kyber-skills install`) that puts a skill in the identity repo, links it into both runtimes so it works immediately, commits, and pushes — so "the agent saved a skill" and "the agent has a skill" stop being different things. The platform converges on its own rather than depending on the agent remembering that command: the in-pod reporter relinks, rescans, and reports on a loop, so a skill an agent simply writes and commits becomes loadable and visible within a couple of minutes. A read-only `GET /api/v1/agents/{name}/skills` plus a Skills tab in Agent Details show what each agent can actually invoke, with its description and origin (own, vendored, or built into the runtime image); each skill is an expandable row, and one with problems opens by default and keeps a problem count visible when collapsed. The report is a scan of the **pod**, not of GitHub: it names skills that are committed but loadable by nothing, malformed or undescribed `SKILL.md` files, vendored skills silently shadowing the agent's own, skill directories written straight into a runtime home, and skills that are not pushed to GitHub — none of which survive a reprovision. There is no write path — adding, changing, and removing skills is done by talking to the agent.
- Feature (agents, api, pwa): **agents can resume their session after an unexpected restart** (kyber#118). A per-agent `sessionResume` toggle (API + Agent Details) makes the runtime pick its previous conversation back up with the harness's native resume (`claude --continue` / `codex resume --last`) after a pod recreate, machine preemption, or crash — session transcripts already live on the agent's durable volume. An intentional restart-session still always starts fresh (it stays the operator's context-clearing tool), a resumed session never replays the startup prompt, and repeated fast failures on a resumed transcript fall back to a fresh session instead of crash-looping. Off by default; takes effect on the next launch.
- Fix (agents, api, pwa): **an invalid model can no longer fail silently.** Writing a model id (fleet default, set-model, or agent create) is now validated against the catalogs the cluster can see, with `force: true` as the escape hatch for a model newer than the last detection poll — previously any string wrote cleanly and every inheriting agent failed each turn while reporting healthy. The boot-time pre-flight probe now captures both output streams (the CLI prints rejections to stdout, which the probe discarded) and reports its raw exit and output; the control plane classifies it with a unit-tested table (`pkg/modelprobe`) instead of an in-image grep. A rejection raises the ModelUnsupported condition carrying the CLI's actual error, surfaces in `blockedReason` and the agent-detail banner (which now leads with checking the model id, not upgrading the runtime), and an inconclusive probe shows as Unknown instead of disappearing.
- Fix (agents): **messages no longer land in a restarting agent's dying session.** Inbound delivery now waits (bounded) for the agent to be Running again before delivering, so a prompt that arrives during a set-model, secret-update, or operator restart is answered by the fresh session instead of the terminating pod.
- Fix (agents): **a graceful pod roll can no longer misreport as a crash.** A reconcile racing the roll's own status update used to classify the deliberately-terminating pod as died — flashing Failed in the console, inflating restartCount, and emitting a false AgentCrashed warning. A recently-deleted pod now waits for the roll's transition; pods stuck Terminating past 60 seconds still take the dead-node recovery path.
- Feature (agents, pwa): **fresh installs now track the latest agent harness while letting each harness choose its default model.** Settings exposes explicit Default and Latest choices for both Claude Code and Codex, while retaining free-form model and version pins. Empty model defaults now boot successfully without a forced model flag, `latest` is installed on each new pod, and any concrete operator selection survives Helm upgrades. New-agent creation inherits both runtime-scoped settings instead of silently pinning the first detected model; its model picker and manual override were removed.
- Feature (agents, pwa): **model choices now come from the authenticated agent that will use them.** Claude Code agents query Anthropic with their existing OAuth or API-key credential, while Codex agents use authenticated app-server `model/list`; both report only model metadata through the status sidecar. Change model reads a per-agent catalog and persists the selection in `spec.model`, so pod recreation keeps it. Harness versions remain public npm data, and the Settings page no longer asks for a platform Anthropic key.
- Fix (agents, pwa): **harness-default agents now report the concrete model they actually use.** The first token snapshot persists its transcript-observed model in `Agent.status.currentModel`, the agent API and detail view expose it as a harness-selected default, and first-session transcript discovery runs every five seconds so dashboard context pressure appears promptly after the first response. Authenticated agents also replay cached model metadata every 30 seconds, while calling the upstream provider only hourly, so a control-plane restart cannot leave an in-memory local catalog empty for an hour.
- Fix (agents, pwa): **authenticated model catalogs require valid provider-reported context windows.** The internal status pipeline no longer replaces windows with an unverified 200K floor. It rejects the whole catalog when any model omits or reports invalid context metadata, leaving the failure visible in reporter logs instead of presenting guessed model-picker or token-budget values.
- Fix (claude-code): **fresh Claude agents no longer stop at the workspace-trust prompt.** Boot now records trust for the resolved identity-repo launch directory, after cloning, rather than trusting the container's earlier `/` working directory. Existing durable Claude configuration is merged in place and self-heals on the next pod boot.
- Feature (pwa, updates): **an available update is now visible from every page, and installable from there.** The control plane has polled the release feed hourly for some time, but the only surface that read the answer was the Settings → Updates card — a page an operator has no reason to open — so a cluster could sit months behind with nothing saying so. The refresh icon beside the cluster version in the header now appears when a newer version is available and opens a dialog describing it: which version, when it was released, and a link to the release notes, followed by what installing costs (the control plane restarts, then every agent restarts and loses its current session). That dialog is now one shared component behind both the header and the Settings card, so the two cannot drift into differently-worded warnings. On a cluster that may not install its own update — ArgoCD-managed, `selfUpgrade` off, or pinned — the icon still appears but the dialog drops the Install button and names what owns the cluster instead, because a GitOps cluster that never mentions being behind is worse than one that cannot act on it itself. `GET /api/v1/updates` gained `latestPublishedAt`, the release's publish date, absent when the source has none (the chart registry behind the `main` channel publishes no date, so an unreleased build legitimately has neither a date nor notes, and the dialog says so). The icon's previous job — offering to reload a tab whose bundle is behind the cluster — is removed: one glyph, one meaning.
- Feature (pwa): **an agent stuck in NeedsAuth can now be restarted from the UI.** The agent detail More menu was empty in that phase, so an agent parked on a credential that was already valid had no control at all and needed a cluster-admin `kubectl annotate` on the Agent object to unwedge. It now offers "Restart pod", which rebuilds the pod using the credentials the agent already has — the fix for the case where the operator supplied a good credential but the controller's one-attempt recovery latch had already claimed it and nothing re-triggered a reconcile. The item deliberately fires `POST /agents/{name}/start`, the only lifecycle edge that exists out of NeedsAuth; wiring it to `/restart` would have been a visibly-clickable no-op. The controller's automatic path is unchanged: it still refuses to retry on its own until the credential genuinely differs, so a click buys exactly one pod create and a still-dead credential lands back in NeedsAuth rather than looping. The Re-authorize panel is untouched and remains the control for a credential that is actually bad.
- Feature (agents): **compact a running agent's context from the UI or the API.** `POST /api/v1/agents/{name}/compact-session` asks the agent's live runtime to summarize its own conversation and continue with a smaller context, without killing the session or rolling the pod — the non-destructive alternative to restart-session. Available on both the Claude Code and Codex runtimes (both use `/compact`), and surfaced as "Compact session" in the agent detail More menu. Runtimes with no compaction answer 501; a 60s per-agent cooldown prevents a double-click from queueing a second full-conversation model call. The response reports that the command was *delivered* — compaction then runs asynchronously on the runtime's own clock. Unrelated to the `transcriptCompaction` Helm key, which reclaims duplicate archive objects in the log bucket.
- Fix (pwa): **a stale browser can no longer be pinned to an old build.** `index.html`, `sw.js`, and `registerSW.js` are served `no-store` — `index.html` names the hashed bundle to load, so a cached copy pinned that client to an old build and reloading could not dislodge it (the reload was answered from cache); a stale `sw.js` was worse, a service worker whose replacement is fetched through the copy being replaced. A miss under `/assets/` now returns 404 instead of falling back to `index.html`: those paths are build output, never client-side routes, and answering with HTML under a 200 and a JavaScript content type let a stale page keep running indefinitely and let a CDN cache HTML under a `.js` URL. Deep links still fall back as before. Content-hashed bundles continue to cache normally.
- Fix (api, pwa): **an expired browser session now prompts for re-authentication instead of dead-ending.** Browser sessions are process-local, so every control-plane restart invalidates every open browser at once — the most common 401 an operator sees, and fully recoverable. It previously surfaced as "invalid browser session" rendered inline by whichever query failed first, with no explanation and no way out. The control plane now returns a distinct `session_expired` code and the embedded PWA opens a re-auth prompt on it. A rejected API key deliberately keeps the generic `unauthorized` code, since re-prompting there would loop.
- Fix (metrics): **token cost estimates now include output and cache-write tokens.** Output tokens were parsed from runtime transcripts but dropped before storage, so the Token Usage panel's Output column was always 0 and output spend never reached the cost estimate; cache-creation tokens were counted but had no rate, pricing them at $0. Output now flows end-to-end (reporter → accumulator → windowed series → API → PWA), provider-rates carries a `cache_creation` rate projected from the LiteLLM feed, and the PWA Token Usage table shows a new "Cache write" column. Pre-upgrade query windows under-report output for up to 7 days (metrics retention) and then self-heal.
- Fix (api): **the in-app Codex device login now actually shows the code.** The panel shipped spinning forever: the control plane reads the code out of the agent by running a small script in the pod as the agent user, and it ran that through `sudo -i` — a login shell, which re-parses the command it is handed and mangled the script's syntax on every poll. The probe answered an error, the handler reported "still starting", and a perfectly good code sat unread in the agent the whole time. It now uses `runuser`, as every other run-as-the-agent path in the platform already does. Caught on kyber-canary; the unit tests fed the parser hand-written output and so never ran the command at all. The panel also stops hiding this class of fault behind a spinner: a probe that could not run at all now reports `failed` with the reason instead of "still starting", which is what let the original bug go unnoticed for a release.
- Feature (api, pwa): **Codex device login now happens in the app, not in a terminal.** Signing an agent in with a ChatGPT subscription meant staring at an embedded read-only terminal and picking a link and a one-time code out of it by hand — awkward on a desktop, worse on a phone. Agent Details now renders them: click **Start device login** and the panel shows a spinner, then the verification link as an ordinary clickable anchor and the code in a monospace block with a one-tap **Copy code** button, plus a countdown to expiry. An expired code says so and offers **Start again** rather than quietly restarting the flow on a timer. Backed by a new read-only `GET /api/v1/agents/{name}/codex-device-auth`, which reports the flow's state (`absent`, `starting`, `ready`, `expired`) by reading the in-pod login session — the Codex CLI has no machine-readable device-auth output, so the platform parses its prompt and degrades to "still starting" rather than guessing if the wording changes. When the flow's countdown origin cannot be read the code is still served without a deadline, and the panel shows no timer rather than a wrong one. The terminal `mode=device-auth` remains on the exec route as a debugging escape hatch; it is just no longer what an operator is shown.
- Fix (api): **starting a Codex device login now works more than once.** A Codex agent on a ChatGPT subscription that had already failed a device login could never be recovered from the UI: "Start device login" answered `204` and showed its success toast, but the agent stayed in `NeedsAuth` forever. The endpoint signals a re-auth by writing `{}` into the agent's Codex credential Secret, and the controller's recovery gate keys on that Secret's `resourceVersion` — but the Secret already holds `{}` on every retry, and Kubernetes does not bump `resourceVersion` for a byte-identical update, so the gate never reopened. It now clears `status.recoveryInput` the way an explicit Start already does, buying exactly one attempt without relaxing the automatic path.
- Fix (api, security): **`?token=` API-key auth is now accepted only on WebSocket upgrade requests.** The query-parameter fallback exists because browsers cannot set an `Authorization` header during the WS handshake, but it was honoured on every route — so a full-scope key pasted into a plain REST URL would land in proxy/ingress access logs and browser history. Plain REST requests must use `Authorization: Bearer`; the PWA already does, and its WebSocket connects (`/events`, exec) are unaffected.
- Docs: installation, operations, and architecture docs generalized for public use (placeholder domains/projects/IDs, generic cluster naming conventions, self-contained `helm install` path as the supported deployment route).
- Chore: repository licensed under Apache 2.0 with standard community files (SECURITY.md, CODE_OF_CONDUCT.md, CONTRIBUTING.md, issue/PR templates).
